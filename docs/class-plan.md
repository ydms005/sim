# 클래스 기능 계획 (아직 만들지 않음)

이 문서는 `0005_member_profile.sql`로 회원 정보(학생/학부모/교사, 이름·학교·학년·반·번호, 담당·학년·반)를
준비하면서 함께 정리해 둔 **다음 단계 계획**입니다. 지금은 구현하지 않고, 가입·내 정보 화면만 준비합니다.

## 하려는 것

- **담임 교사**: 자기 반 학생의 **활동정리**를 관리·입력할 수 있게 합니다. 예: 생기부(학교생활기록부) PDF를
  학생 대신(또는 함께) 넣어 주는 것.
- **교과 교사**: 자기가 수업하는 학생들의 활동정리를 관리·입력할 수 있게 합니다. 예: 동아리·수행평가·활동
  보고서를 학생 대신(또는 함께) 넣어 주는 것.
- **학생**: 담임·교과 교사가 넣어 준 자료를 자기 활동정리 화면에서 그대로 볼 수 있게 합니다.

즉, 지금은 "학생 개인만 보는 활동정리"이지만, 앞으로는 "교사가 반/수업 단위로 학생 활동정리에 자료를
넣어 줄 수 있는" 구조로 넓히는 것이 목표입니다.

## 참고

운영자가 다른 프로젝트(wonedu.org)에서 이미 만든 적 있는 클래스 기능을 참고해서 설계할 예정입니다.
(화면 구성, 반 배정 방식, 권한 구조 등을 그대로 가져오기보다는 이 사이트 구조에 맞게 다시 설계합니다.)

## 아직 정하지 못한 것 (open questions)

- **PDF 서버 저장 필요**: 지금 활동정리의 PDF 원본은 **학생 기기(브라우저)에만** 저장되고 서버로 올라오지
  않습니다. 교사가 자료를 넣어 주려면 학생이 아닌 사람이 접근할 수 있어야 하므로, 최소한 그 자료는
  **서버(Supabase Storage)에 암호화해 저장**해야 합니다. 용량은 1인당 또는 학교당 상한(예: 1GB)을 두는
  방향을 검토합니다.
- **동의·보관 기간**: PDF/활동정리를 서버에 저장하면 개인정보 보관 기간, 동의 방식(학생 동의? 보호자 동의?),
  탈퇴·졸업 시 삭제 시점을 새로 정해야 합니다.
- **반 배정 방식**: 학생과 담임·교과 교사를 같은 반/수업으로 묶는 방법을 정해야 합니다. 후보:
  - 교사가 반(또는 수업) 코드를 발급하고, 학생이 그 코드를 입력해 들어오는 방식
  - 관리자가 명단(엑셀 등)으로 일괄 배정하는 방식
  - 학교·학년·반이 같은 학생을 교사가 목록에서 골라 추가하는 방식
- **권한 범위**: 교과 교사가 볼 수 있는 학생 범위(자기 수업 학생만?), 담임이 바뀌거나 학생이 반을 옮길 때
  자료를 어떻게 옮길지도 정해야 합니다.

## 이번(0005) 마이그레이션이 미리 준비해 둔 것

- `profiles.user_type`에 `parent`(학부모) 추가, `school`·`grade`·`class_no`·`student_no`(학생),
  `teacher_role`·`teacher_grade`·`teacher_class`(교사) 컬럼 — 나중에 반 배정의 기초 데이터로 씁니다.
- 교사 계정은 관리자 승인(`teacher_status`)을 거쳐야 '선생님'으로 확인되므로, 클래스 기능을 열 때도 이
  승인 여부를 그대로 활용할 수 있습니다.
