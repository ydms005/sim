# data/ — 사이트 데이터 원본 (CSV · 엑셀)

이 폴더의 CSV 파일과 엑셀(.xlsx) 파일이 사이트에 보이는 모든 데이터의 **원본**입니다.
`npm run dev`·`npm run build` 를 실행하면 `scripts/build-data.mjs` 가 먼저 돌면서 CSV와 엑셀을 검사·합치고
`public/data/*.json` 을 새로 만듭니다. `public/data/` 는 자동 생성물이라 Git에 올리지 않습니다.

> 대학 목록은 실제 대학 기준이지만, 지금 CSV에 든 경쟁률·모집요강·자료실·소식은 모두 **개발용 샘플**입니다.
> **2단계(엑셀 업로드)** 부터는 선생님이 **엑셀**로 실제 자료를 정리해 올리면, 엑셀에 적은 대학의 샘플이 그 엑셀 내용으로 바뀝니다.
> 가장 쉬운 방법은 사이트의 **데이터 관리 화면**(<https://ydms005.github.io/sim/admin>, 바닥글의 '데이터 관리' 링크)을 쓰는 것입니다 — 아래 [엑셀로 관리하기](#엑셀로-관리하기-2단계).

```
data/universities.csv ─┐
data/competition.csv  ─┤                          ┌─ public/data/universities.json
data/guidelines.csv   ─┤                          │
data/resources.csv    ─┼─ scripts/build-data.mjs ─┼─ public/data/univ/{대학ID}.json
data/news.csv         ─┤  (검사 → 합치기 → 변환)    │
data/**/*.xlsx        ─┘                          └─ public/data/trends.json
public/files/univ/{대학ID}/*.pdf  ← 모집요강·자료실이 가리키는 PDF (Git에 포함)
```

검사·합치기 규칙은 `scripts/lib/dataset.mjs` 한 곳에 있고, 배포 빌드(`build-data.mjs`)와 데이터 관리 화면의 '파일 검사'가 **같은 코드**를 씁니다.
그래서 관리 화면에서 검사를 통과하면 배포에서도 (PDF 파일이 실제로 올라가 있는 한) 같은 결과가 나옵니다.

## 엑셀로 관리하기 (2단계)

### 엑셀 파일 규칙

- `data/` 폴더(하위 폴더 포함)의 모든 `.xlsx` 파일을 읽습니다. 파일 이름은 자유입니다(예: `data/2027/건국대-경쟁률.xlsx`).
  Excel 이 파일을 열어 둘 때 생기는 `~$` 로 시작하는 임시 파일은 무시합니다. 예전 형식 `.xls` 는 읽지 못하니 `.xlsx` 로 저장하세요.
- **시트 이름**으로 데이터 종류를 정합니다(앞뒤 공백 무시).

  | 시트 이름 | 같은 내용의 CSV |
  |---|---|
  | `대학목록` | universities.csv |
  | `경쟁률` | competition.csv |
  | `모집요강` | guidelines.csv |
  | `자료실` | resources.csv |
  | `소식` | news.csv |

  `안내` 시트(양식의 설명 시트)는 읽지 않고, 그 밖의 이름은 경고만 하고 무시합니다. 한 파일에 여러 시트를 넣어도, 시트 하나만 넣어도 됩니다.
- **열 이름(머리글)** 은 아래 CSV 설명과 똑같습니다. 값이 있는 첫 행(보통 1행)이 머리글입니다. 머리글이 없으면(첫 행부터 데이터) 오류로 알려 줍니다.
- 아무것도 없는 행·열(맨 아래·오른쪽의 빈 칸, 중간의 빈 행)은 건너뜁니다. 값의 앞뒤 공백은 지웁니다.
- 숫자는 **숫자 칸이든 글자 칸이든** 상관없습니다(`16`, `'16`, `1,234` 모두 됨). `3.5` 처럼 소수는 정수 칸에서 오류입니다.
- `날짜` 는 **엑셀 날짜 칸**(표시 형식 무관)이어도, `2026-09-09` 처럼 글자로 적어도 됩니다. 날짜 칸은 `YYYY-MM-DD` 로 바꿔 읽습니다.
- 셀 안 줄바꿈(Alt+Enter)은 `요약`(소식)·`부제`(자료실)에만 쓸 수 있습니다. 다른 열에 있으면 오류입니다.
- 오류 메시지는 `[data/2027.xlsx › 경쟁률 12행] '모집인원' 값 '다섯' 은(는) 정수가 아닙니다.` 처럼 **파일 › 시트 행 번호** 로 알려 줍니다(엑셀 왼쪽의 행 번호와 같음).
- 값 검사 규칙(허용 값·정수·학년도·날짜·URL·PDF 경로·중복 등)은 CSV와 똑같습니다.

### CSV와 합쳐지는 규칙

| 시트 | 규칙 |
|---|---|
| **대학목록** | 엑셀 행이 같은 `대학ID` 의 CSV 행을 **덮어씁니다**(upsert). CSV에 없는 대학ID 면 새 대학으로 추가합니다. |
| **경쟁률·모집요강·자료실·소식** | 어느 엑셀 파일에든 **대학 X 의 행이 하나라도 있으면**, 그 종류(시트)의 **대학 X CSV 행은 모두 버리고** 엑셀의 행만 씁니다. 엑셀에 없는 대학의 CSV 행은 그대로입니다. |

- 예: `경쟁률` 시트에 건국대(3) 행이 3개 있으면, competition.csv 의 건국대 361행은 쓰지 않고 엑셀의 3행만 사이트에 나옵니다.
  이때 건국대의 모집요강·자료실·소식 CSV 행은 그대로입니다(그 시트들에는 건국대 행이 없으므로).
  그래서 **한 대학의 한 종류 자료는 빠짐없이 모두** 엑셀에 적어야 합니다(관리 화면의 '현재 데이터 엑셀로 내려받기' 로 받아서 고치면 편합니다).
- 버린 CSV 행은 빌드 기록에 `안내 [data/competition.csv] 대학ID 3 의 경쟁률 361행은 쓰지 않습니다 — 엑셀(…)의 자료로 바꿉니다.` 로 표시됩니다.
- 같은 대학의 행이 **여러 엑셀 파일**에 나뉘어 있으면 모두 합칩니다. 합친 뒤에도 중복 검사(예: `대학ID+학년도+모집단위+전형명`)는 그대로이고,
  중복이면 두 위치를 함께 알려 줍니다: `중복된 행입니다 (…) — [data/a.xlsx › 경쟁률 3행]과 같습니다.`
  `대학목록` 도 엑셀끼리는 같은 대학ID 가 두 번 나오면 오류입니다.
- `hasData`·`hasDetail`·`trends.json` 은 **합친 결과**로 계산합니다(예: 샘플이 없던 대학도 엑셀에 경쟁률을 넣으면 '경쟁률 제공' 배지가 붙음).
- 엑셀 내용이 CSV와 완전히 같으면 사이트 결과(`public/data`)도 똑같습니다(관리 화면에서 내려받은 '현재 데이터' 엑셀을 그대로 넣어도 바뀌는 것 없음).

### 데이터 관리 화면 (/admin)

사이트 바닥글의 **데이터 관리** 링크(<https://ydms005.github.io/sim/admin>)에서 서버 없이 브라우저만으로 할 수 있습니다.

1. **엑셀 양식 내려받기** — 빈 양식(설명 시트 `안내` + 머리글만 있는 5개 시트) 또는 **현재 데이터**(전체 또는 한 대학)를 엑셀로 받습니다.
2. **파일 검사** — 고친 엑셀(여러 개 가능)과, 엑셀의 `파일` 열에 적은 PDF 를 끌어다 놓으면 **현재 배포된 사이트 데이터와 합쳐** 빌드와 같은 규칙으로 검사하고,
   오류·경고를 파일·시트·행 번호별로 보여 줍니다. 대학별로 경쟁률 등이 몇 건 추가·삭제·변경되는지도 요약합니다.
   - PDF: 엑셀이 가리키는 경로의 파일 이름과 같은 PDF 를 함께 넣으면 그 경로로 올립니다. 현재 사이트 데이터가 쓰는 PDF 와 배포된 사이트에 실제로 있는 PDF 는 있는 것으로 봅니다.
     어디서도 확인하지 못한 경로는 오류가 아니라 **경고**로 알려 줍니다(그대로 올리면 배포 빌드에서 '파일을 찾을 수 없습니다' 오류가 납니다).
   - CSV 를 넣으면(파일 이름이 `competition.csv` 처럼 같아야 함) 그 종류의 데이터를 **통째로** 바꿉니다(`data/` 의 같은 CSV 를 교체).
3. **미리보기** — 검사를 통과한 데이터로 이 브라우저 탭에서만 사이트를 봅니다(화면 아래 '미리보기 중' 띠 → '미리보기 끝내기'). 실제 사이트는 바뀌지 않습니다.
4. **GitHub에 올리기(선택)** — GitHub 개인 액세스 토큰(fine-grained, `ydms005/sim` 저장소의 Contents: Read and write 만)을 붙여 넣으면,
   엑셀은 `data/파일이름.xlsx`, PDF 는 엑셀에 적은 경로(`public/files/univ/…`)로 **커밋 하나**로 올립니다. 오류가 있으면 올리지 않습니다.
   토큰은 그 브라우저의 localStorage 에만 저장되며 '토큰 지우기' 로 지울 수 있습니다. 저장소·브랜치는 `src/config.ts` 의 `GITHUB_REPO`·`GITHUB_BRANCH` 입니다.
5. **자동 배포** — 올리면 GitHub Actions 가 다시 검사·빌드해 약 2분 뒤 사이트에 반영됩니다.

관리 화면은 공개 주소지만, 토큰 없이는 아무것도 바꿀 수 없습니다(검사·미리보기는 내 브라우저 안에서만 일어남).

**토큰 없이 올리기** — GitHub 웹에서 `data/` 폴더를 열고 **Add file → Upload files** 로 엑셀을 올린 뒤 **Commit changes**.
PDF 는 `public/files/univ/{대학ID}/` 에 같은 방법으로 올립니다. 올리기 전에 관리 화면의 '파일 검사' 로 먼저 확인하세요.

**주의** — 저장소에 이미 있는 엑셀과 **같은 이름**으로 올리면 그 파일이 바뀝니다. 예전 파일에만 있던 대학의 행은 사라지고, 그 대학은 다시 CSV(샘플) 자료로 돌아갑니다.
관리 화면의 검사·미리보기는 '지금 배포된 결과'에 새 엑셀을 더하는 방식이라 이 경우를 그대로 반영하지 못합니다. 헷갈리면 파일마다 다른 이름을 쓰세요.

### 샘플 데이터 없애기

1. 엑셀로 실제 자료를 올린 대학은 그 종류의 샘플이 **자동으로** 빠집니다(위 합치기 규칙).
2. 남은 샘플을 모두 없애려면 `competition.csv`·`guidelines.csv`·`resources.csv`·`news.csv` 에서 머리글(1행)만 남기고 행을 지웁니다
   (`universities.csv` 는 실제 대학 목록이므로 지우지 않습니다). 필요 없어진 샘플 PDF(`public/files/univ/{대학ID}/`)도 지워도 됩니다 —
   검사에서 가리키는 PDF 가 없으면 오류로 알려 주므로, CSV 행을 먼저 지우세요.
3. 사이트의 모든 경쟁률·자료가 실제 자료가 되면 `src/config.ts` 의 `IS_SAMPLE_DATA` 를 `false` 로, `NOTICE` 문구도 알맞게 바꿉니다.

## 파일과 열

모든 파일은 **UTF-8 CSV**, 첫 줄은 아래의 한글 열 이름입니다. 값에 쉼표·줄바꿈·큰따옴표가 있으면 값 전체를 `"…"` 로 감싸고,
값 안의 큰따옴표는 `""` 로 두 번 적습니다. 예: `"인용"으로 시작` → `"""인용""으로 시작"`, `서울, 경기` → `"서울, 경기"`.
열 순서는 바뀌어도 되지만 열 이름은 정확히 같아야 합니다. 모르는 열은 경고만 하고 무시합니다.

**큰따옴표 짝 검사** — 짝이 맞지 않는 따옴표가 하나 있으면 그 뒤의 여러 행이 값 하나로 합쳐져 조용히 사라질 수 있으므로 엄격하게 검사합니다.
- `"…"` 로 감싼 값의 닫는 따옴표 뒤에는 공백과 쉼표·줄바꿈만 올 수 있습니다. `"인용"으로 시작` 처럼 뒤에 글자가 이어지면 오류입니다.
  앞 행에서 연 따옴표가 뒤 행에서 닫혔다면 `[… 5행] 2행에서 시작한 큰따옴표 값이 5행에서 닫혔는데 …` 처럼 두 줄 번호를 모두 알려 줍니다.
- 파일 끝까지 닫히지 않은 따옴표는 오류입니다.
- 줄바꿈은 **news.csv 의 `요약`, resources.csv 의 `부제`** 에만 쓸 수 있습니다. 다른 열(대학ID·대학명·학년도·모집단위·전형명·숫자·날짜·제목·파일·링크 등)에
  줄바꿈이 있으면 따옴표 짝이 맞지 않아 여러 행이 합쳐진 것으로 보고 오류로 알립니다.
- `요약`·`부제` 가 여러 줄인데 그 안에 `3,2026-09-08,…` 처럼 CSV 행으로 보이는 줄이 있으면 경고합니다(빌드는 계속되므로 경고를 꼭 확인하세요).

### universities.csv — 대학 목록 (필수)

| 열 | 설명 | 예 |
|---|---|---|
| 대학ID | 1 이상의 정수. **한 번 정하면 바꾸거나 재사용하지 않습니다**(주소 `/univ/3` 이 이 값입니다). | `3` |
| 대학명 | 공식 교명 | `건국대학교` |
| 지역 | `서울 경기 인천 부산 대구 광주 대전 울산 세종 강원 충북 충남 전북 전남 경북 경남 제주` 중 하나 | `서울` |
| 설립구분 | `국립` · `공립` · `사립` 중 하나 | `사립` |
| 캠퍼스 | 같은 이름의 대학이 여러 행일 때 구분용. 없으면 비움 | `서울캠퍼스` |
| 홈페이지 | 대학 대표 홈페이지(`https://…`). 확실하지 않으면 비움 | `https://www.konkuk.ac.kr` |
| 주소 (선택) | 도로명주소 | `서울특별시 광진구 능동로 120` |
| 우편번호 (선택) | 도로명 우편번호 | `05029` |
| 대표전화 (선택) | 대표전화번호 | `02-450-3114` |
| 영문명 (선택) | 학교 영문명 | `Konkuk University` |
| 설립일자 (선택) | `YYYY-MM-DD` | `1931-05-15` |

- `대학명+캠퍼스` 조합은 중복될 수 없습니다.
- 사이트에서는 대학명 가나다순으로 보여 줍니다(같은 이름이면 대학ID 순).
- **주소·우편번호·대표전화·영문명·설립일자는 선택 열**입니다. 없어도 오류가 아니며(예전 CSV·엑셀과 그대로 호환), 있으면 대학정보 탭의
  '기본 정보' 카드에 표시됩니다. 직접 입력해도 되고, 아래 **표준데이터로 채우기**로 한 번에 채울 수 있습니다.

### 대학알리미 표준데이터로 채우기 (선택 열 자동 입력)

`data/raw/전국대학및전문대학정보표준데이터.csv` 는 공공데이터포털의
[전국대학및전문대학정보표준데이터](https://www.data.go.kr/data/15107736/standard.do)(한국대학교육협의회 제공, CP949/EUC-KR 인코딩) 원본입니다.
`data/raw/` 폴더는 빌드가 읽지 않는 **원본 보관용** 폴더이고(`data/*.csv` 만 읽습니다), 새 버전을 받으면 같은 이름으로 덮어써 두면 됩니다.

```bash
npm run data:import-standard
```

- `data/raw/전국대학및전문대학정보표준데이터.csv` 에서 4년제(대학교·교육대학·산업대학) 학교를 찾아 `data/universities.csv` 의
  대학명(+캠퍼스, `국립` 접두 차이 포함)이 같은 행에 **주소·우편번호·대표전화·영문명·설립일자**를 채웁니다.
- **대학ID·대학명·지역·설립구분·캠퍼스는 절대 바꾸지 않습니다.**
- **홈페이지는 우리 값이 비어 있을 때만** 채웁니다. 이미 값이 있으면 그대로 두고, 표준데이터와 다르면 화면에 '차이'로만 보여 주고 바꾸지 않습니다
  (입학처 대신 다른 홈페이지가 확인된 경우 등 직접 확인 후 넣은 값을 존중하기 위해서입니다).
- 표준데이터에는 있지만 우리 목록(4년제 201곳 기준)에 없는 학교(대개 폐교·통합), 반대로 우리 목록에 있는데 표준데이터에서
  찾지 못한 대학은 **자동으로 추가·삭제하지 않고** 화면에 목록만 보여 줍니다. 새 대학을 추가하려면 [위 안내](#이렇게-추가하세요)대로 직접 추가하세요.
- 실행 후 `npm run data` 로 검사·미리보기를 다시 확인하고, 결과가 맞으면 `data/universities.csv` 를 커밋하세요.

## 이렇게 추가하세요

**대학 추가** — universities.csv 맨 아래에 새 행을 붙이고, 지금까지 쓴 가장 큰 대학ID + 1 을 줍니다. 폐교·통합된 대학도 ID를 다른 대학에 다시 쓰지 않습니다(행을 지우면 그 ID는 비워 둡니다).

**경쟁률 추가** — competition.csv 에 `대학ID,학년도,모집단위,전형명,전형유형,모집인원,지원자수` 행을 붙입니다. 순서는 상관없습니다.

**PDF 추가** — PDF를 `public/files/univ/{대학ID}/` 에 넣고(파일 이름은 영문·숫자·`-` 권장), guidelines.csv 또는 resources.csv 에 `files/univ/{대학ID}/파일이름.pdf` 로 적습니다.
- 파일·폴더 이름에 **`#` `?` `%` 는 쓸 수 없습니다**(검사 오류). 경로가 그대로 웹 주소가 되는데, `#`·`?` 뒤는 주소에서 잘려 나가고 `%` 는 인코딩 표시로 해석되어
  검사를 통과해도 사이트에서 PDF가 열리지 않기 때문입니다. 한글·공백·괄호는 써도 됩니다(예: `2027 수시 모집요강 (최종).pdf`).
- CSV의 경로는 **대소문자까지** 실제 파일과 같아야 합니다. Windows·macOS 에서는 `Guideline.pdf` 로 적어도 `guideline.pdf` 가 열리지만,
  GitHub Pages 는 대소문자를 구분해 찾지 못하므로 검사에서 오류로 알려 줍니다.
- 맨 앞의 `public/`·`/`, 역슬래시(`\`), `//` 는 알아서 정리합니다. `..` 는 쓸 수 없습니다.

경쟁률이 아직 없는 대학이어도 됩니다. 모집요강·자료실·소식 중 하나라도 있으면 그 대학의 상세 파일이 만들어져 해당 탭에 바로 보입니다(`hasDetail`).
외부에 있는 PDF는 `https://` 주소를 그대로 적어도 됩니다. 다만
- `http://` 주소는 오류입니다. 사이트가 HTTPS(GitHub Pages)라서 브라우저가 혼합 콘텐츠로 막아 뷰어에서 열 수 없습니다.
- 주소가 `.pdf` 로 끝나지 않으면(예: `download.do?id=…`) 경고만 합니다. PDF 파일을 바로 내려주는 주소인지 확인하세요.
- 그 서버가 CORS를 허용하지 않으면 사이트의 PDF 뷰어에서 열리지 않을 수 있습니다.

**확인** — `npm run data` 를 실행합니다(엑셀도 함께 검사합니다). 문제가 있으면 `[data/competition.csv 12행] '모집인원' 값 '다섯' 은(는) 정수가 아닙니다.` 처럼
파일·줄 번호와 함께 모든 오류를 보여 주고, `public/data` 는 건드리지 않은 채 끝납니다(종료 코드 1 → 배포도 중단됨).

검사 항목: 필수 열 · 알 수 없는 대학ID · 지역/설립구분/전형유형/분류 값 · 정수가 아닌 인원 · 음수 · 학년도·날짜 형식 · URL 형식 · 중복 행 ·
전형명별 전형유형 일관성 · 참조한 PDF가 `public/` 에 대소문자까지 똑같은 이름으로 있는지 · PDF 경로에 `#` `?` `%`·제어 문자가 없는지 ·
외부 PDF는 `https://` 인지 · 큰따옴표 짝(닫는 따옴표 뒤의 글자 · 닫히지 않은 따옴표 · 요약·부제가 아닌 열의 줄바꿈, 위 '큰따옴표 짝 검사' 참고).

- universities.csv 의 한 행이 오류(예: 지역 `서울시`)이면 그 대학은 목록에서 빠집니다. 이때 다른 파일에서 그 대학ID를 쓰는 행마다
  '알 수 없는 대학ID' 오류를 내지 않고, 파일마다 `대학ID 3 의 361행은 대학ID 검사를 건너뛰었습니다 — universities.csv 4행의 오류를 먼저 고치세요.`
  라는 경고 한 줄만 보여 줍니다. universities.csv 자체를 읽지 못했을 때(따옴표 오류·필수 열 없음 등)도 다른 파일은 대학ID 검사를 건너뛰고
  파일마다 경고 한 줄만 보여 줍니다. 오류 목록은 최대 100건까지 출력합니다.

**Excel 사용 시** — "CSV UTF-8(쉼표로 분리)(*.csv)" 형식으로 저장하세요. 일반 "CSV" 로 저장하면 EUC-KR 이 되는데, 이 경우에도 읽기는 하지만 경고를 출력합니다.
내용만 지운 행은 Excel 이 `,,,,,,` 처럼 쉼표만 있는 행으로 저장합니다. 이런 행은 빈 행으로 보고 건너뛰며, 파일마다 몇 개를 건너뛰었는지 경고로 알려 줍니다.

## indicators.csv · academyinfo-ids.csv — 대학알리미 공시 지표 (선택)

대학정보 탭의 '대학 주요 지표(대학알리미 공시)' 카드에 쓰는 자료입니다. 직접 손으로 관리하는 파일이 아니라
`scripts/fetch-academyinfo.mjs` 가 대학알리미(공공데이터포털) OpenAPI 로 자동으로 만듭니다. 둘 다 **없어도 오류가 아니며**
(카드가 그냥 보이지 않음), Git 에 커밋해 두면 사이트 빌드 때 `public/data/indicators.json` 으로 합쳐집니다.

| 파일 | 내용 |
|---|---|
| `academyinfo-ids.csv` | 대학ID · 대학알리미 학교ID(schlId) · 학교명 매칭 결과(참고용 기록) |
| `indicators.csv` | 대학ID,공시연도,지표,값,단위,출처 — 대학정보 탭에 그대로 표시 |

### 실행 방법

1. **[data.go.kr](https://www.data.go.kr)** 에서 아래 두 API를 신청하고(보통 즉시 또는 몇 시간 안에 승인) 인증키(서비스키)를 발급받습니다.
   - [전국대학및전문대학 표준데이터 — 대학 기본 정보](https://www.data.go.kr/data/15158963/openapi.do)
   - [대학알리미 학생 현황](https://www.data.go.kr/data/15158684/openapi.do)
2. **저장소에 등록해 자동으로 돌리기(권장)** — 저장소 **Settings → Secrets and variables → Actions → New repository secret** 에서
   이름 `DATA_GO_KR_KEY`, 값에 인증키를 넣고 저장합니다. 그 뒤 **Actions** 탭 → **대학알리미 지표 업데이트** → **Run workflow** 를 누르면
   `data/indicators.csv`·`data/academyinfo-ids.csv` 를 새로 만들어 바뀐 내용이 있을 때만 자동으로 커밋·배포합니다
   (`.github/workflows/update-academyinfo.yml`, 기본으로 매달 1일에도 자동 실행됩니다).
3. **내 컴퓨터에서 직접 실행하기** — data.go.kr 이 **해외 서버(GitHub Actions)의 요청을 막아** 2번이 실패할 수 있습니다.
   이때는 컴퓨터에서 실행한 뒤 결과 파일 두 개를 GitHub 웹의 **Add file → Upload files** 로 `data/` 에 올리세요.
   ```bash
   DATA_GO_KR_KEY=발급받은키 npm run data:fetch
   ```
4. 실행하면 대학알리미의 학교 코드 목록에서 `data/universities.csv` 의 대학명(+캠퍼스)과 같은 학교를 찾아
   **정원내 신입생 경쟁률·신입생 충원율·재학생 충원율** 을 가져옵니다. 인증키가 아직 등록되지 않았거나(승인대기)
   호출 한도를 넘으면 데이터.go.kr 이 알려 주는 오류 메시지를 그대로 보여 주고 멈춥니다.

### 주의

- 반드시 `npm run data` 를 한 번 더 실행해 빌드에 오류가 없는지 확인한 뒤 커밋하세요(워크플로는 자동으로 확인합니다).
- 지표 값의 뜻(정원내/정원외, 수시·정시 합산 등)은 대학알리미 공시 기준을 그대로 따릅니다. 카드에는
  '대학 전체 기준(수시·정시 합산)' 안내를 함께 보여 줍니다.
- 인증키는 절대 커밋하지 마세요. GitHub Actions 에서는 Secrets 로만 넣고, 로컬에서는 환경 변수로만 넘깁니다.

## hasData 와 hasDetail

`public/data/universities.json` 의 각 대학에는 두 값이 붙습니다.

| 값 | 뜻 | 사이트에서 쓰는 곳 |
|---|---|---|
| `hasData` | competition.csv 에 그 대학의 경쟁률 행이 있음 | '경쟁률 제공' 배지, 경쟁률 추세, 학과 검색 |
| `hasDetail` | `public/data/univ/{대학ID}.json` 이 있음 = 경쟁률·모집요강·자료실·소식 중 하나라도 있음 | 대학 상세 탭(대학정보·모집요강·지난 경쟁률·자료실·소식)이 이 파일을 불러옴 |

모집요강 PDF는 경쟁률 발표보다 몇 달 먼저 나오므로, 모집요강만 올린 대학은 `hasData: false` · `hasDetail: true` 가 됩니다.
이 대학의 모집요강·자료실·소식 탭은 정상적으로 보이고, 대학정보·지난 경쟁률 탭은 '경쟁률 자료가 없다'고 안내합니다.

## 샘플 데이터 다시 만들기 (개발용)

```bash
npm run data:sample   # scripts/generate-sample-data.mjs → competition/guidelines/resources/news.csv
npm run data:pdf      # scripts/generate-sample-pdfs.mjs → public/files/univ/{id}/*.pdf
npm run data          # 검사 후 public/data/*.json 생성
```

- `data:sample` 은 시드 고정 난수를 쓰므로 몇 번 실행해도 같은 CSV가 나옵니다. 모집단위·전형 설정은 `scripts/sample-profiles.mjs` 에 있습니다.
  샘플 대상이 아닌 대학의 행이 CSV에 있으면(실제 데이터를 넣기 시작했다면) 덮어쓰지 않고 멈춥니다. 강제로 덮어쓰려면 `npm run data:sample -- --force`.
- `data:pdf` 는 **Playwright(Chromium)** 가 필요합니다. 프로젝트 의존성에는 넣지 않았으므로 전역 설치를 사용합니다.
  ```bash
  npm i -g playwright && npx playwright install chromium   # 처음 한 번
  npm run data:pdf                   # guidelines.csv·resources.csv 에 적힌 PDF를 모두 다시 생성
  npm run data:pdf -- --missing      # 없는 파일만 생성(직접 넣은 실제 PDF는 건드리지 않음)
  npm run data:pdf -- --only=3,5     # 특정 대학ID만
  ```
  전역 모듈을 찾지 못하면 `NODE_PATH=$(npm root -g) npm run data:pdf` 로 실행하세요.
